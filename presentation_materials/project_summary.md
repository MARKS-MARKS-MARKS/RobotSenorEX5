# 实验五项目复用材料：面向泛化性与鲁棒性的多层柜体感知与交互系统

## 1. 汇报主线

本项目面向服务机器人真实整理场景：柜内物品类别不固定、摆放位置不固定、柜体层数和拍摄视角可能变化，且深度图存在噪声和空洞。因此系统目标不是只在单张固定图片上完成识别，而是构建一套具有泛化性与鲁棒性的 RGB-D 感知与人机交互流程。

整体分为两个层面：

- 感知层面：围绕数据采集、开放词汇语义识别、柜层识别、空位识别与 3D 定位，强调如何适应不同物品、不同柜体、不同视角和深度噪声。
- 人机交互层面：围绕 Web 界面、手动 ROI、参数调节、新物体类别/尺寸输入和推荐结果展示，强调如何让用户参与调整、验证和复现实验。

可以用一句话概括：

系统用 RealSense RGB-D 获取空间信息，用 Grounding DINO 实现开放词汇识别，用点云几何提取柜层和空位，再通过交互界面让用户调整场景先验和任务参数，从而提升真实柜体场景下的泛化性与鲁棒性。

## 2. 任务链路总览

```text
数据采集
  RealSense RGB-D 对齐 / session 保存 / replay
        ↓
开放词汇语义识别
  Grounding DINO + yml 候选词表 + 未知障碍
        ↓
柜体 ROI 与检测后处理
  自动/手动/多边形 ROI + 去重 + 宽框拆分 + 单层过滤
        ↓
柜层识别
  ROI 点云反投影 + 体素降采样 + 水平平面带 + RGB-D 边缘兜底
        ↓
空位识别与 3D 定位
  层内占用投影 + 物理尺寸约束 + 相机内参反投影
        ↓
人机交互与推荐
  Web 可视化 + 新物体类别/尺寸 + 两阶段推荐 + 实时调参
```

## 4. 感知层面：按任务展开

### 4.1 数据采集：RGB-D 对齐与可复现实验

实现位置：`exp5/realsense_io.py`、`exp5/pipeline.py`

#### 任务目标

获取同一时刻、同一视角下的彩色图和深度图，使 RGB 图像中的每个像素都能找到对应深度，用于后续 3D 定位。

#### 基础实现

1. 使用 RealSense SDK 开启两路数据流：
   - Color：640x480，BGR/RGB 图。
   - Depth：640x480，Z16 原始深度。
2. 使用 `rs.align(rs.stream.color)` 将深度图对齐到彩色相机坐标系。
3. 读取彩色相机内参：

```text
fx, fy, ppx, ppy, depth_scale
```

4. 保存 session：

```text
color.png
depth.png
intrinsics.json
meta.json
```

#### 实现原理

RealSense 的彩色相机和深度相机物理位置不同，原始 RGB 与 Depth 并不天然一一对应。对齐操作根据相机标定关系将深度重投影到彩色相机视角。这样 Grounding DINO 在 RGB 图上输出的检测框，可以直接在同一区域读取深度值。

深度图中的原始数值需要乘以 `depth_scale` 转换为米：

```text
Z_m = depth_raw * depth_scale
```

后续所有三维坐标都基于米制深度和相机内参计算。

#### 泛化性与鲁棒性设计

- 支持 live、capture、replay 三种模式。现场相机可用时实时运行，硬件不稳定时可用保存的 session 复现实验。
- 支持多帧中值融合，静态柜体场景下可抑制随机深度噪声。
- 支持深度补洞：仅在局部邻域有足够有效深度时填补无效点，避免把大面积未知区域误填成可用平面。

### 4.2 开放词汇语义识别：从固定类别到可扩展候选词

实现位置：`exp5/detector.py`、`exp5/config.py`、`configs/default.yaml`

#### 任务目标

识别实验要求的四类物品，同时适应真实场景中同一类别下的不同具体实例，例如 cup、mug、glass 都可归入 Tableware。

#### 基础实现

使用 Grounding DINO 作为开放词汇检测器。配置文件中给每个实验类别设置多个候选词：

```yaml
detector:
  prompts:
    Cutlery:
      - fork
      - knife
      - spoon
      - chopsticks
    Tableware:
      - cup
      - mug
      - plate
      - bowl
    Breakfast:
      - cereal
      - bread
      - oatmeal
      - yogurt
    Soft Drink:
      - cola
      - soda
      - beverage bottle
      - juice
```

程序通过 `flatten_prompts()` 将候选词展开，并建立：

```text
具体候选词 → 实验类别
```

例如：

```text
cup → Tableware
soda can → Soft Drink
cereal box → Breakfast
knife → Cutlery
```

#### 实现原理

Grounding DINO 是文本条件目标检测模型。它接收图像和文本 prompt，输出与文本语义匹配的图像区域。相比闭集检测器，模型不局限于固定类别编号，而是可以根据输入文本寻找目标。

项目没有只输入四个抽象类别名，而是输入大量具体物品词。这样做的原因是：

- 具体词更容易和图像外观对应，例如 `cup` 比 `Tableware` 更具体。
- 同一类物品外观变化大，可以通过多个词覆盖。
- 添加新词不需要重新训练模型，只需修改 yml。

#### 泛化性与鲁棒性设计

1. **yml 候选词可扩展**

   如果测试场景中出现新物品，可以直接在 `configs/default.yaml` 中加入候选词。例如：

```yaml
Tableware:
  - teacup
  - ceramic bowl
  - saucer
Soft Drink:
  - sprite bottle
  - coke can
```

   这使系统能适配新的品牌、外观和名称。

2. **类别独立阈值**

   不同类别容易误检的程度不同，因此项目支持：

```yaml
category_thresholds:
  Cutlery: 0.28
  Tableware: 0.30
  Breakfast: 0.33
  Soft Drink: 0.30
```

   对容易误检的类别提高阈值，对容易漏检的类别降低阈值。

3. **低置信候选降级为未知障碍**

   某个候选像四类物品但置信度不够时，不直接把它归类，也不完全忽略，而是在高于 unknown 阈值时作为未知障碍保留。这样可以降低错误分类带来的语义风险，同时避免把真实物体当成空位。

### 4.3 未知障碍识别：不强行分类但保留物理占用

实现位置：`exp5/detector.py`、`exp5/geometry.py`

#### 任务目标

实验要求四类之外的干扰物体不能强行赋予标签，但机械臂放置时必须避开它们。因此系统需要把未知物体作为障碍物保留。

#### 基础实现

配置 `unknown_prompts`：

```yaml
unknown_prompts:
  - object
  - item
  - package
  - container
  - box
  - food package
  - toy
  - book
```

Grounding DINO 检测到这些候选后，系统将其 `category` 设为 `None`，再经过 `semantic_unknown_obstacles()` 转为 `Obstacle`。

#### 实现原理

系统把语义类别和物理占用分开：

- 已知物体：有实验类别，用绿色框显示，参与类别统计和放置推荐。
- 未知障碍：没有实验类别，用灰色框显示，只参与避障和空位切分。

未知候选还会经过几何过滤：

1. 分数必须超过未知障碍阈值。
2. 框面积、宽度、高度不能太小。
3. 框中心必须落在某一层。
4. 相对层板面积不能过大。
5. 与已知物体重叠过多时去除，避免重复占用。

#### 泛化性与鲁棒性设计

- `unknown_prompts` 可在 yml 中继续添加，例如 snack、bag、remote、can、carton。
- 未知障碍不参与四类统计，避免错误语义污染结果。
- 未知障碍参与空位占用，避免模型“不知道是什么”的物体被误认为可放置区域。

### 4.4 柜体 ROI：限制有效感知区域

实现位置：`resolve_cabinet_roi*()`、`web_static/app.js`

#### 任务目标

只在柜体内部检测层板和空位，避免把墙面、桌面、背景区域当成柜内空位。

#### 基础实现

系统支持默认归一化 ROI：

```yaml
cabinet_roi_norm: [0.156, 0.05, 0.93, 0.98]
```

检测、层板识别、空位计算和 3D map 都被限制在 ROI 或 ROI mask 内。

#### 实现原理

ROI 过滤包括两部分：

1. 检测框中心需要落在 ROI 内。
2. 检测框与 ROI 的重叠比例需要超过阈值。

对于多边形 ROI，系统生成 mask。空位检测时，只有 ROI mask 内占比足够的列才可能被视为空位。

#### 泛化性与鲁棒性设计

- 自动 ROI：通过 Canny 边缘、Hough 直线、暗色区域和有效深度连通域估计柜体范围。
- 手动 ROI：网页上可在原图拖拽柜体区域。
- 多边形 ROI：可处理相机斜视时柜体投影不是矩形的问题。
- ROI 可通过命令行或 yml 固化，方便不同柜体重复实验。

### 4.5 检测后处理：减少误检、重框和跨层错误

实现位置：`exp5/detector.py`、`exp5/geometry.py`

#### 任务目标

开放词汇模型在真实柜体中容易出现重复框、大框合并和跨层误检。后处理用于把语义检测结果变成适合几何推理的稳定输入。

#### 实现原理

1. **中心距离与 IoU 去重**

   多个候选框中心很近或重叠很大时，认为它们表示同一物体。系统优先保留：

   - 已知类别框。
   - 置信度更高的框。
   - 面积更紧的框。

2. **宽框深度拆分**

   如果一个检测框过宽，系统在框内读取深度 crop：

```text
背景深度 = crop 有效深度的较远百分位
前景 = 深度明显小于背景深度的像素
```

   然后对前景做连通域分析。如果存在多个独立前景连通域，就将一个大框拆成多个小框。

3. **单层约束**

   物体框必须满足：

   - 中心落在某一层。
   - 上下边界不能明显跨越层板。

   不满足条件的跨层框会被丢弃。

#### 泛化性与鲁棒性设计

- 去重避免多个 prompt 命中同一物体造成重复统计。
- 宽框拆分利用深度信息修正开放词汇模型的合并框问题。
- 单层约束利用柜体结构先验，避免一个误检框同时影响上下两层空位。

### 4.6 柜层识别：点云水平平面带与边缘兜底

实现位置：`exp5/geometry.py`

#### 任务目标

提取柜体中每一个有效水平层板，并在 RGB 图中用红色框标出层级。

#### 实现流程

```text
ROI 内深度点
→ 有效深度过滤
→ 反投影为 3D 点云
→ 体素降采样
→ 按相机竖直方向 Y 分箱
→ 统计每个高度带的点数和横向覆盖
→ 选择宽支撑水平平面带
→ 合并相邻候选
→ 生成层间边界
→ 输出 Shelf box
```

#### 详细原理

1. **点云反投影**

   对 ROI 内每个有效深度像素 `(u, v, Z)`：

```text
X = (u - ppx) * Z / fx
Y = (v - ppy) * Z / fy
Z = depth(u,v)
```

   得到相机坐标系下的点云。

2. **体素降采样**

   将空间按约 1 cm 体素划分，同一体素内点只保留代表点。这样保留层板的大尺度形状，同时减少噪声和计算量。

3. **水平平面带判断**

   柜子层板在三维空间中是横向延伸的水平支撑结构，因此在某个竖直高度附近会出现大量点。系统按 `Y` 值分箱，对每个高度带统计：

   - 点数是否足够。
   - 横向覆盖是否达到柜宽比例。
   - 深度跨度是否合理。

   点数多且横向覆盖宽的高度带被认为是层板候选。

4. **由边界生成层区域**

   检测到的水平带可视为层与层之间的分界线。系统将 ROI 顶边、内部层板线、ROI 底边组合成边界序列，相邻边界之间就是一层：

```text
Shelf_i = [roi_x1, boundary_i, roi_x2, boundary_{i+1}]
```

5. **RGB-D 边缘兜底**

   当深度点不足时，在 ROI 内计算灰度行均值并求纵向梯度。层板边缘通常是横向长边缘，对应梯度峰值。系统可用这些峰值修正或补齐层板边界。

#### 泛化性与鲁棒性设计

- 不强制固定三层，可通过配置推断层数或设定最大/最小层数。
- 支持 `shelf_boundaries_norm` 或 `shelf_boundaries_px` 手动覆盖层板边界。
- 点云方法适合不同层高；RGB-D 边缘兜底适合深度缺失或层板材质不稳定情况。

### 4.7 空位识别与 3D 定位：从像素空白到真实可放区域

实现位置：`find_empty_spaces()`、`subtract_occupied_from_empty_spaces()`、`attach_3d_to_detections()`

#### 任务目标

识别每层中能够安全放置新物体的空位，并输出空位中心真实 3D 坐标。

#### 实现流程

```text
输入 Shelf + 已知物体 + 未知障碍
→ 物体/障碍框安全膨胀
→ 投影为当前层占用列
→ 得到 free_cols
→ 扫描连续空闲区间
→ 根据深度把物理尺寸换算成像素阈值
→ 输出 EmptySpace 框、size_m、center_m
```

#### 详细原理

1. **层内占用建模**

   对每一层建立横向占用数组。已知物体和未知障碍的框先向外膨胀，作为安全余量；如果该框与当前层有足够竖直重叠，就把它的横向范围标记为占用。

2. **连续空闲区搜索**

   对每层从左到右扫描：

```text
occupied_cols:  True 表示被占用
free_cols:      False 的反集
```

   连续空闲列长度超过阈值后，才生成候选空位。

3. **物理尺寸约束**

   空位最小宽高不是固定像素值，而是由真实尺寸换算：

```text
min_w_px = required_width_m  * fx / Z
min_h_px = required_height_m * fy / Z
```

   其中 `Z` 是当前层代表深度。这样同样 50 像素的空位，在远近不同的层上会对应不同真实宽度。

4. **空位中心 3D 坐标**

   空位中心像素为：

```text
cx = (ex1 + ex2) / 2
cy = (ey1 + ey2) / 2
```

   使用层代表深度反投影，得到：

```text
center_m = (X, Y, Z)
```

5. **物体 3D 坐标**

   对已知物体，系统用检测框内有效深度中值计算物体中心，并额外输出框底边中心 `contact_center_m`，更接近物体与层板接触点。

#### 泛化性与鲁棒性设计

- 空位判断结合真实物理尺寸，避免只按图像像素判断。
- 安全膨胀避免贴边放置。
- 未知障碍参与占用，避免开放词汇未分类物体造成碰撞风险。
- 最终会用稳定后的物体/障碍再次切分空位，避免蓝色空位框覆盖已显示物体。

## 5. 人机交互层面

### 5.1 Web 界面：围绕实验流程组织

实现位置：`exp5/web_server.py`、`exp5/web_static/index.html`、`app.js`

Web 界面分为三块：

1. 左侧数据与检测控制：
   - 选择 `data/sessions` 中的 RGB-D session。
   - 选择检测器：GroundingDINO / Replay / None。
   - 勾选自动 ROI、Unknown 障碍。
   - 手动框 ROI、清除 ROI。
   - 重新检测当前图片。

2. 中央可视化：
   - 识别结果图。
   - 俯视图。
   - 3D 地图。
   - 原图。
   - 深度图。

3. 右侧结果面板：
   - Objects / Shelves / Spaces / Obstacles 数量统计。
   - 推荐位置说明。
   - 物体列表和置信度。
   - 状态提示。

### 5.2 两阶段交互：检测与推荐分离

交互流程：

```text
第一步：重新检测当前图片
  运行 Grounding DINO + 层板识别 + 空位检测
  保存 artifacts

第二步：根据新物体选择空位
  不重新检测图像
  只读取已有空位
  根据新物体类别和尺寸重新过滤与评分
```

设计意义：

- Grounding DINO 推理较慢，检测和推荐分离后，用户可以快速尝试不同新物体。
- 适合展示“同一感知结果下，任务输入变化如何改变推荐位置”。
- 也便于报告中做对比测试，例如不同物体尺寸导致候选空位数量变化。

### 5.3 新物体类别与尺寸输入

用户可以输入：

```text
名称/类别：cup、Tableware、Breakfast...
尺寸：0.14,0.12,0.12
```

系统处理方式：

1. `normalize_category_name()` 将具体名称映射到类别。
2. 尺寸写入 `active_item_size_m`。
3. 空位过滤时要求：

```text
space_width_m  >= item_width_m  + safety_margin
space_height_m >= item_height_m + safety_margin
```

4. 若多个空位都能放下，再进行推荐评分。

### 5.4 推荐策略

推荐函数：`recommend_placement()`

评分思路：

```text
score = 空位面积得分
```

如果已有同类物体：

```text
score += 同类加分
score += 同层加分
score -= 到最近同类物体的 3D 距离 * 距离权重
```

含义：

- 没有同类物体时，选更大的安全空位。
- 有同类物体时，优先放在同类附近。
- 同层空位额外加分，使推荐更符合整理习惯。

### 5.5 实时参数控制

实时模式下支持 OpenCV 控制面板，可调：

- 新物体类别。
- 新物体宽、高、深。
- Grounding DINO 全局阈值。
- 四类类别独立阈值。
- Unknown 阈值。
- 检测间隔。
- 多帧融合帧数。
- ROI 范围。
- 空位最小宽高。
- 稳定器漏检保持帧数和平滑系数。

这些参数直接对应感知链路中的不确定因素，便于现场根据画面调整。
